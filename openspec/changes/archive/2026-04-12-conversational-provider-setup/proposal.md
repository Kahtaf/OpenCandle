## Why

OpenCandle's current first-run setup blocks the user with a two-phase modal wizard (LLM → Alpha Vantage + FRED), front-loads five API-key decisions before the user has done anything, and only handles two of the five credentialed providers. The remaining three (Finnhub, Brave, Exa) have no onboarding path at all — users must find the config file to unlock news, fundamentals, and premium search. For non-technical users who are not finance-savvy, the wizard is friction before value: a first-time user sees "Connect Alpha Vantage for fundamentals, DCF, and earnings?" and has no context for why that matters. OpenCandle is pre-launch — there are no existing users to migrate — so this is the moment to replace the wizard with a conversational, just-in-time provider system inspired by OpenClaw's agent-led UX, before the current flow calcifies into a product expectation.

## What Changes

- **Delete the finance-provider prompt from first-run startup.** Remove `runFinanceSetup` from `session_start`. No data-provider questions at first run. (Note: LLM sign-in still requires a model to run against — see next bullet.)
- **Auto-select a default model after LLM auth.** After successful OAuth or API-key entry, if the selected provider has a designated default model in the registry, the setup flow auto-selects it and skips the model picker. The user is only asked to pick a model if zero or multiple defaults apply. This collapses the current two-step (auth → model picker) into one step for the common path.
- **Add agent-voice welcome message seeded via `sendMessage`.** After first-run setup completes, the extension seeds a visible assistant message via the Pi `sendMessage` API (`display: true`). The message explains what OpenCandle can do, suggests concrete example prompts, and mentions `/connect` as an escape hatch. An explicit `welcomeShownAt` flag in onboarding state ensures it appears exactly once per installation — not tied to whether the user has configured providers.
- **Introduce a two-tier just-in-time setup pattern.** The pattern differs by provider tier:
  - **Hard providers** (Alpha Vantage, FRED): no meaningful fallback. The first workflow that needs one pauses and offers a four-option prompt (connect now / continue without / snooze 7 days / never ask). At most one hard-provider prompt fires per workflow run — additional missing hard providers silently degrade to gap notes.
  - **Soft providers** (Finnhub, Brave, Exa): have fallbacks (sentiment-summary treats Finnhub as optional enrichment; Brave falls back to DDG; Exa falls back to keyless MCP). These SILENTLY use their fallback and emit a post-answer gap note in the final output ("used DDG for search — run `/connect search` for premium results"). They never pause mid-workflow.
- **Add a provider descriptor registry.** Single source of truth for `{ id, displayName, category, tier, signupUrl, envVar, configPath, unlocks, fallback, snoozeDays }`. Every setup pathway (startup, `/connect`, just-in-time prompts, gap notes) iterates the registry. Replaces hardcoded per-provider logic in `setup.ts`.
- **Add a typed `ProviderCredentialError` at the provider layer.** Providers stay pure fetchers — they throw this typed error when a credential is missing or stale, rather than returning custom error strings. `wrapProvider` re-throws `ProviderCredentialError` instead of swallowing it as `status: unavailable`. Tools catch the error at their boundary and convert it into a `credential_required` tool result envelope.
- **Intercept `credential_required` at the Pi extension `tool_result` hook.** Pi already exposes `pi.on("tool_result", handler)` (see `@earendil-works/pi-coding-agent` `types.d.ts:726`). The OpenCandle extension registers a `tool_result` handler that inspects every tool result, detects `credential_required`, consults onboarding state, and drives the prompt or degrade path. This is NOT a `SessionCoordinator` feature.
- **Emit skipped results via tool-result `content` text, not `details` JSON.** Pi provider adapters serialize tool results from `content` to the LLM; `details` is UI/test metadata only (verified in `pi-ai/dist/providers/*`). The skipped placeholder is a tagged text block in `content` (e.g., `[OPENCANDLE_SKIPPED provider=alpha_vantage remediation="run /connect company-financials"]`) with one system-prompt instruction telling the model how to surface it.
- **Extract a shared `promptUser` helper from `ask_user`.** The current `ask_user` tool has its UI branches (`ctx.ui.select`, `ctx.ui.input`, `ctx.ui.confirm`) and headless-fallback logic trapped inside its `execute` closure. Extract those into a reusable `promptUser(ctx, options)` function. `ask_user` becomes a thin wrapper. The `tool_result` interception handler calls `promptUser` directly for the four-option prompt — no fake `ask_user` tool synthesis.
- **Add a `/connect` Pi command with friendly aliases.** `/connect` opens a picker listing all providers with human labels ("Alpha Vantage — company financials", "FRED — economic data", "Finnhub — company news", "Exa / Brave — web search"). `/connect <alias>` routes to the matching provider (e.g., `/connect financials`, `/connect economy`, `/connect news`, `/connect search`). Machine ids and category slugs work too. The command calls the shared `runProviderConnect(id)` function.
- **Defer the `connect_provider` agent tool to a future change.** The agent tool was intended to let the model proactively offer setup in free-form conversation, but `createTool()`-based tools drop the `ctx` argument in `agentToolToPiTool` (`src/pi/tool-adapter.ts:15`) and the name fails the allowed-name regex in `src/tool-kit.ts`. Implementing it requires the raw Pi tool pattern (like `trigger_twitter_login`) and opens questions about when the model should call it versus wait for orchestrator-driven prompts. Out of scope for v1. The orchestrator-driven flow (`tool_result` interception + `promptUser`) covers the core UX; `/connect` covers manual reconfiguration.
- **Handle env-var credential precedence in `runProviderConnect`.** `src/config.ts:84-93` gives env vars precedence over file config. If a user has `ALPHA_VANTAGE_API_KEY` set in their environment, writing a new key to `config.json` does nothing — subsequent tool calls still see the env var. `runProviderConnect` SHALL detect when the active credential for a provider is env-sourced and tell the user plainly: "Alpha Vantage is currently set via the `ALPHA_VANTAGE_API_KEY` environment variable. To change it from here, unset that variable first. Otherwise, update the variable directly in your shell profile."
- **Expand onboarding state to per-provider + welcome flag.** Replace the single `financeSetupStatus` enum with `providers: Partial<Record<ProviderId, ProviderOnboardingEntry>>` and add `welcomeShownAt?: string`. Enables per-provider snooze, never-ask, last-prompt tracking, and one-shot welcome.
- **Replace Pi-chrome copy with OpenCandle voice** in the surrounding setup UI. Keep `LoginDialogComponent` for OAuth callback handling only. Build a small OpenCandle-branded flow for the API-key entry path using `ctx.ui.input` directly.
- **BREAKING** (structural, not user-facing since pre-launch): `OnboardingState.financeSetupStatus` field is removed. `hasFinanceKeys`, `runFinanceSetup`, `ALPHA_VANTAGE_SIGNUP_URL`, `FRED_SIGNUP_URL` constants in `src/pi/setup.ts` are deleted. `FinanceProviderReadiness` type is deprecated in favour of registry-driven readiness. `wrapProvider` gains a re-throw branch for `ProviderCredentialError`.

## Capabilities

### New Capabilities
- `provider-registry`: Descriptor-based source of truth for all credentialed third-party providers (Alpha Vantage, FRED, Finnhub, Brave Search, Exa). Defines provider metadata, default-model hints, unlock descriptions, fallback copy, tier (hard/soft), snooze policy, and friendly aliases. Consumed by setup flows, `/connect` command, credential interception, and gap-note generation.
- `conversational-provider-setup`: First-run LLM sign-in with auto-selected default model, seeded-assistant-turn welcome message via `sendMessage`, just-in-time hard-provider prompts via `promptUser` driven from a Pi `tool_result` extension hook, silent soft-provider degradation with post-answer gap notes, per-provider onboarding state with snooze/never-ask/welcome semantics, and the `/connect` command with friendly aliases for reconfigurable sectioned setup.

### Modified Capabilities
- `tool-extensibility`: `AgentTool.execute` return contract gains a convention for signaling missing/stale credentials via a tagged `[OPENCANDLE_CREDENTIAL_REQUIRED ...]` text block in `content`. A typed `ProviderCredentialError` is added at the provider layer for upstream throw-to-catch plumbing. `wrapProvider` gains a re-throw branch for this error type. The Pi `tool_result` extension hook becomes the interception point for converting credential-required results into prompts or degrade paths.

## Impact

- **Affected source (setup + extension)**: `src/pi/setup.ts` (delete `runFinanceSetup`/`hasFinanceKeys`/signup URL constants, rewrite `runLlmSetup` to auto-select default model, replace API-key path with OpenCandle-branded `ctx.ui.input` flow, replace setup copy), `src/pi/opencandle-extension.ts` (register `connect` command, register `tool_result` handler, seed welcome message via `sendMessage`).
- **Affected source (new modules)**: `src/onboarding/providers.ts` (registry with `tier` and default-model fields), `src/onboarding/connect.ts` (shared `runProviderConnect` with env-precedence detection and auth-vs-network error distinction), `src/onboarding/credential-interceptor.ts` (the `tool_result` handler logic as a pure function for testability), `src/onboarding/prompt-user.ts` (extracted from `ask-user.ts`).
- **Affected source (state)**: `src/onboarding/state.ts` — new `Partial<Record<ProviderId, ProviderOnboardingEntry>>` shape plus `welcomeShownAt?: string`. Version bumped to 2.
- **Affected providers**: `src/providers/alpha-vantage.ts`, `fred.ts`, `finnhub.ts`, `exa-search.ts`, and the Brave branch of `web-search.ts` — each throws a typed `ProviderCredentialError` with a `{ reason: "missing" | "stale" }` discriminator on missing/stale credentials. Existing throw sites for `"API key may be invalid"` are replaced.
- **Affected infra**: `src/providers/wrap-provider.ts` — re-throws `ProviderCredentialError` instead of catching it as `status: unavailable`, so the error reaches the tool layer.
- **Affected tools**: Every tool under `src/tools/` that calls one of the five credentialed providers catches `ProviderCredentialError` at its `execute()` boundary and returns a tool result whose `content` carries a tagged `[OPENCANDLE_CREDENTIAL_REQUIRED ...]` text block. The `details` field may carry the same info as structured metadata for UI/tests but is not the LLM contract.
- **Affected interaction tool**: `src/tools/interaction/ask-user.ts` — UI branches lifted into a new exported `promptUser(ctx, opts)` helper; `ask_user.execute` becomes a thin wrapper. This is the same helper the `tool_result` interceptor calls for the four-option prompt.
- **System prompt**: `src/system-prompt.ts` gains one instruction explaining how to surface `[OPENCANDLE_SKIPPED ...]` tagged blocks in the final answer.
- **Dependencies**: No new npm dependencies. Reuses existing `openInBrowser` helper, existing config persistence, existing Pi extension hook (`pi.on("tool_result", ...)`).
- **Config shape**: `src/config.ts` unchanged at the `Config` type level. `FinanceProviderReadiness` and `getFinanceProviderReadiness` are deleted. A new helper describing *source* of each credential (`env` vs `file` vs `absent`) is added to support `runProviderConnect`'s env-precedence handling.
- **User data**: `~/.opencandle/onboarding.json` schema changes (no migration because product is pre-launch).
- **Tests**: New unit tests live under `tests/unit/` per the existing repo layout in `tests/AGENTS.md`. Provider-registry tests, onboarding-state snooze/welcome semantics, `credential-interceptor` pure-function decision table, `/connect` command pathways, provider-level `ProviderCredentialError` emission, tool-level catch-and-emit behavior. Existing setup tests rewritten.
- **Out of scope** (explicit non-goals for this change): `connect_provider` agent tool (deferred), re-auth flow for expired LLM OAuth tokens, footer status line provider indicators, restyling `LoginDialogComponent` internals, changing any free provider (Yahoo/CoinGecko/Reddit/SEC EDGAR/Fear & Greed), failure-as-invitation patterns for stale credentials as a separate observability feature.
