# Saved-State Personalization: Close the E1/E2 Gaps

## Why

The dominant historical competitive-loss class is personalization over saved state, and the E1/E2 eval suites (landed 2026-07-04) recorded two live failures against it:

- **E1 (`tests/evals/cases/live-multi-turn-coreference.eval.ts:22`):** in a session with a seeded AMD portfolio lot, turn 3 "and compare it to the one I hold" carried prior-turn NVDA into entities but **failed to resolve AMD from the saved holding**. Root cause (verified): saved market-state reaches only the *system prompt* (`buildSavedMarketStateContext`, `session-coordinator.ts:931`) — the **router** never sees the user's holdings, so it cannot resolve holding references.
- **E2 (`tests/evals/cases/saved-market-state.eval.ts:52`):** the scorer checks the latest `opencandle-route-context` entry for fixture symbols/values, but `ResolvedTurnContext` (`src/routing/turn-context.ts:37-53`) carries no saved-state summary — the data lives only in the system prompt path. The eval's own `// PROMOTE` comment states the fix: "Remove OPENCANDLE_EVAL_KNOWN_FAIL_E2 once opencandle-route-context carries the saved market-state summary."

## What Changes

- **Router sees saved holdings (E1).** `RouterInputContext` gains a compact saved-state block (portfolio symbols with share counts, watchlist symbols). Gating decision (the existing `shouldIncludeSavedMarketStateContext` cannot gate router *input* — it reads `routeKind`, the router's own *output*): the block is included under a **deterministic pre-router finance-context gate** — finance signal in the current text or prior turns, the same pattern the conversational risk-preference recovery guard already uses. A turn with no finance context anywhere gets no block (the tennis-court class stays clean); the router's `profileSnapshot` precedent (unconditional) is deliberately NOT followed, to keep holdings out of non-finance prompts. The router prompt renders the block as a *data* section alongside the existing prior-turns rendering — additive data injection only; no instruction text changes (the same authorization boundary as the I3 tally block).
- **Deterministic held-symbol backstop (E1 stability).** New sibling logic in `postProcessRouterOutput` beside the existing options-screener held-symbol correction (`router.ts` ~:397-432, which fires only for `options_screener` from current-text extraction — it is a neighbor, not a base to extend): when the current text contains a holding-coreference phrase ("the one I hold", "my position", "my shares") and the router output resolved no saved holding, saved portfolio symbols are added to `entities.symbols` (entities, never slots) with a `held_symbol_saved_state` diagnostic. If multiple saved holdings could match and nothing disambiguates, no symbol is forced — ambiguity is the ask-user path's job, not a guess. `postProcessRouterOutput`'s context parameter (currently `Pick<RouterInputContext, "priorTurns" | "profileSnapshot">`) widens to carry the saved-state block for this and the provenance guard below.
- **Deterministic slot-provenance guard.** Nothing today stops the router LLM, having seen AMD in the saved-state block, from emitting it as a `user`-sourced slot (the existing downgrade only matches prior-turn symbols). Extend the provenance downgrade in `postProcessRouterOutput`: a user-sourced symbols slot containing a symbol absent from the current text and prior turns but present in the saved-state block is downgraded to source `memory` (an existing `SlotSource` value) with a `symbols_slot_provenance_saved_state` diagnostic.
- **Route-context carries the summary (E2).** `ResolvedTurnContext` gains `savedMarketState: { included: boolean, summary?: string }` where `summary` is exactly the text the system-prompt path injects (one serialization, reused). Plumbing (verified — the entry is appended at input-handling time, before `before_agent_start` builds the system prompt): (1) a new public coordinator accessor computes the summary during `handleLlmRouterTurn`; (2) inclusion is gated on `output.routeKind !== "pass_through"` at entry time (`workflowType`/`fallbackContext`, the gating's other inputs, do not exist yet — `included` reflects the routeKind-time branch of the gating, which is what the E2 scorer needs); (3) the summary passes into `buildResolvedTurnContext` via a new `options` field (it has no DB access); (4) `buildSystemPrompt` prefers `resolvedTurnContext.savedMarketState.summary` when present and keeps its direct `buildSavedMarketStateContext` call for non-router turns. Non-router turns (`/analyze` dispatch, rules paths) have no `ResolvedTurnContext` and therefore never carry `savedMarketState` in a route-context entry — fine for E2, which tests routed turns.
- **Eval promotion.** Remove the `OPENCANDLE_EVAL_KNOWN_FAIL_E2` and `OPENCANDLE_RUN_KNOWN_FAIL_EVALS` gates from E2/E1 per their PROMOTE comments; both remain usually-tier live evals (they need a live model), now expected to pass.

## Non-Goals

- No router prompt *instruction* changes; the hard prompt-integrity gate applies — only a data block is added to prompt assembly.
- No slot-provenance changes: saved-state-derived symbols land in `entities`, never as `user`-sourced slots (the E1 assertions enforce this).
- No expansion of what saved-state text contains (the existing capped summary builder is reused verbatim).
- No change to pass-through gating: non-finance turns still get no saved-state context anywhere (existing tests must keep passing).
- No `/forget` interaction changes (I4 remains backlogged; the new router-visible surface must be listed in the forget-command change's suppression surfaces when that is scheduled — add a note to that change's proposal, nothing more).

## Failure-mode guards (encode as tests)

- The tennis-court class: a saved portfolio must not convert a pass-through turn into a routed finance turn — gating runs before the block is built.
- The backstop must not fire when the user names a different explicit ticker ("compare NVDA to TSLA" with saved AMD adds nothing).
- Router prompt size: the saved-state block is capped (8 portfolio + 8 watchlist symbols, matching the existing builder's caps).
