# Changelog

## [Unreleased]

### Added

- Public docs now present three ways to run OpenCandle. A new "Ways to Run OpenCandle" page compares the web app, the local GUI, and the terminal in one table a first-time user can decide from, and a new "How the Web App Works" page explains in plain language where an entered API key lives, why the no-storage relay exists and exactly which endpoints it forwards, every third party involved at runtime (Cloudflare, StackBlitz, direct data providers, ticker-line.com), what is stored in the browser, and the honest caveat that browser storage is not a secure vault, closed with a small architecture diagram. Both pages join the docs navigation, llms.txt, sitemap, and markdown mirror.
- The local and hosted browser GUI now have a dedicated Settings page at `/settings`, reached from a gear entry in its own sidebar group, with a left section rail covering Model, Data providers, Preferences, Notifications and automation, Diagnostics, and Data and privacy. Each section is deep-linkable at `/settings/<section>`, the rail collapses to a scrollable tab strip at narrow widths, and hosted-only rows are absent rather than disabled in the local app.
- Settings now shows what the agent has quietly saved about the user. A Preferences section lists every stored preference (such as a learned risk profile) and every saved tool default with its value, source, and timestamps, and each row can be deleted behind a confirmation, after which it no longer enters the agent's prompt context. New list and delete commands back the section on the local WebSocket path with a trusted HTTP fallback and on the hosted browser runtime, the payload never carries credential material, and deletions persist across hosted checkpoints.
- A reusable typed-confirmation dialog now guards the most destructive hosted action: clearing all browser data requires typing DELETE before the button enables, replacing the native browser confirm.

- Saved-collection pages in the local and hosted browser GUI now share one list-header primitive and one detail-rail page layout. The header keeps the page title and its primary action on a single line, every tab carries its item count, and the rename control belongs to the active tab: hidden until hover or focus on pointer devices, and always visible at a touch-sized target on small screens. The layout gives the primary table the available width, pins a fixed-width detail rail to the right at desktop widths, narrows that rail on smaller desktops, and stretches both regions to the page height so a short list no longer floats over an empty canvas.
- Hosted OpenCandle now includes an auditable, no-storage Cloudflare provider relay with exact upstream policies, bounded bodies and time, generic errors, disabled application and invocation logs, no persistence bindings, pseudonymous network rate limiting, version negotiation, browser-local provider keys, and capability-gated HTTP-backed tools. Native X/Reddit CLIs, shell and dynamic-package tools, and background alerts, notifications, and reports remain local-only.
- An installable hosted PWA now runs the real Pi/OpenCandle agent loop in browser-hosted Node with no OpenCandle application server, persists canonical Pi sessions and compatible SQLite market state in OPFS, supports a live-tested direct Polymarket tool path, coordinates writable follower tabs with epoch-safe failover, deduplicates logical runs and mutations, and provides offline read/export, integrity-checked atomic import, update checkpointing, and clear-secrets/clear-all controls. The existing local GUI and TUI retain their native Node, filesystem, provider, and SQLite paths.
- Agent-developer guardrails now provide canonical `typecheck` and `gates` scripts, a safe worktree bootstrap command, and checked-in delegation and resume contracts.
- First-run model setup in the local and hosted browser GUI is now an onboarding dialog. It opens on a brand introduction, continues through three steps explaining what OpenCandle does and how it sources evidence, and ends on a step that connects a model. Steps advance by swipe, by circular side controls, by clickable step dots, or by arrow keys from those dots. The dialog opens automatically when setup is required, closes with Escape or its close control, does not reopen until setup has been satisfied and later becomes required again, and hands focus to the chat composer on close so drafting stays available. Managing keys from the composer opens the connect step on its own, without the intro deck. Provider credentials are entered through a reusable two-step flow, choosing a provider and then entering its key, that mounts standalone for future settings surfaces, keeps hosted key-retention choices with the key being saved, and reports empty-field, pending, and provider-validation states inline instead of through toasts. New reusable `Carousel` and `RadioGroup` primitives back it, built on `embla-carousel-react` and Radix, and the screenshot harness gained first-run onboarding capture phases.
- Model-setup errors shown inline are no longer also raised as toasts. A toast mounts its own dismissable layer, and Escape reaches only the topmost layer, so the duplicate toast was silently preventing the setup dialog from closing with Escape. Unrelated errors still toast, and the socket path now reports every failed key save inline rather than only rejections matching a fixed message prefix.

### Changed

- The hosted PWA docs page was rewritten as a lean "Web App Quickstart" at the same URL: open web.opencandle.app, connect a key, what works versus what needs the local app, install as an app, data controls, and moving research to the local app. It moved from Guides into Start here, the provider relay operations page moved from Reference into Build with the other contributor pages, and the stale claim that Finnhub and London Strategic Edge are disabled in the web app was corrected: both work once the user supplies their own key.
- The public homepage, FAQ, README, and every docs page now describe three surfaces instead of two. The hero offers "Try it in your browser" beside the npx install command, the header links the web app, the FAQ answers where data is stored per surface and that nothing needs to be installed, structured data lists Web among the operating systems, and claims like "stays on your machine" and "requires Node.js" are scoped to local installs. The public-doc link checker skips web.opencandle.app so release builds do not probe production.
- Data-provider setup in the browser GUI moved from the command palette catalog into Settings. The catalog now offers workflows and tools only, while every registry provider renders as a status row in Settings with its configured, env-managed, snoozed, never-ask, or not-configured state and expands into the same api-key, external-tool, or reachability builder it had before. Legacy provider drawer links redirect into the settings section, diagnostics remediation buttons navigate there, and hosted rows whose provider cannot run in the browser say they are local-only instead of offering setup that cannot succeed.
- Diagnostics moved under Settings. The report content, session checks, and data-quality bands are unchanged, the old `/diagnostics` address redirects to `/settings/diagnostics`, and the sidebar Market State group no longer carries a Diagnostics entry.
- Managing model keys now happens on the Settings Model section instead of a dialog. The composer model chip's manage action, the failed-run repair card, and diagnostics model remediation all navigate to `/settings/model`, which renders the existing connect panel plus a reasoning-effort control; the composer chip keeps its quick model and thinking switcher, and first-run onboarding is unchanged.
- Hosted data management moved from the runtime footer into Settings, and the footer itself is gone. Export, import, install update, clear secrets, and clear all live in the Data and privacy section, reached from the sidebar like any other page, and the local app shows a read-only readout of where its state lives instead of destructive controls. Runtime state now appears as a transient pill floating at the top centre of the page, mounted once for the sidebar-open, sidebar-collapsed, and mobile chrome alike, which says the runtime is preparing, that the browser is offline, or what failed, and offers to install a waiting update in the same pill shape. It takes no layout space and no pointer events beyond itself, so the primary action on watchlists, portfolios, and alerts keeps receiving its own clicks. A ready runtime with nothing waiting shows no pill at all, so the app no longer carries a permanent status bar or a standing "running in this browser" message. The shared shell exposes the pill through a host-neutral slot, so the local GUI renders nothing there. The sidebar header that used to hold it is now one row in both the local and hosted GUI: the OpenCandle wordmark, which no longer truncates at the sidebar's width, and a right-aligned pair of new-chat and collapse controls, replacing the full-width New chat button. The mobile session drawer carries the same row, so New chat stays one tap away, and the search field is unchanged.
- The daily report schedule is now also editable from Settings alongside a read-only row stating whether webhook delivery is configured and how automation runs; the Reports page keeps its configure entry point, and both dispatch the same configure action.
- The GUI symbol page now fills the desktop canvas and interprets the numbers it already had. The price block carries a strip of horizon returns, the distance from the 52-week high, the day range, and the session's volume against its 30-day average, all derived from fetched history, so a horizon the history cannot reach is absent rather than shown as zero or a dash. A key levels card states the 52-week high and low and the 20 and 50 day averages with each level's signed distance from the current price, and every row can open the existing alert sheet already set to that level, with the sheet still deciding the currency, the distance hint, and what is valid. A trend summary says in plain English where the price sits against its 20, 50, and 200 day averages and ends in one sentence, computed rather than written by a model. When the price history behind those figures is a retained copy served while the provider is unreachable, the strip, the key levels, and the trend summary each say which date that history stops at instead of reading as current market context. Those cards join the saved position, the alerts on the symbol, watchlist membership, and the action chips in a fixed detail rail at desktop widths; below that breakpoint the page stacks hero, chart, position, key levels, fundamentals, and company profile in that order. Which sections exist and what the strip calls each stat now come from the instrument's own type instead of a guess read off the ticker string, so a currency pair, an index, and a commodity are no longer mistaken for equities, a type without fundamentals says so once instead of rendering an empty card, and an instrument whose type cannot be resolved keeps its quote, chart, and saved context. Action chips fill the chat box and put the cursor in it without sending anything, and every writer-only action keeps its existing read-only state in a follower window.
- The GUI alerts page keeps its plain-English rules and tightens how they read. The rule sentence is now each row's title under its ticker, the long chain of observed values behind it collapses into one short status that expands on demand, and the expanded line still explains why an armed rule has not fired yet. Repeat state and the pause, edit, and delete controls form one quiet cluster on the right that appears on hover at desktop and stays visible at full size on touch, with deletion confirmed in a dialog. The separate alert log and notifications cards are now a single Activity feed: a firing already wrote both an alert event and a notification, so it appears once, carrying its unread state and its Mark read action, while notifications from other sources keep their own row. Activity rows are one line of title, state, and date, the internal delivery-channel label is gone, a failed delivery is named instead, and an activity feed with nothing in it collapses to one line rather than a second empty card.
- Creating or editing an alert now opens on the rule it will save, written in the same words the saved rule row uses and restated live as the form changes, with its repeat window underneath in human units, stated in a unit the cooldown divides evenly into so a rule saved elsewhere with a 90 minute cooldown does not read as hourly. Each condition option carries a one-line description of what it watches, a price threshold prefills from the symbol's current quote with a quiet note of how far the level sits from it as the level is typed, the field names the currency that level is read in and accepts sub-cent prices instead of rounding them to zero, the previewed level is priced in that quote's own currency rather than assumed to be dollars, a prefilled level leaves when the symbol it was read from is replaced so it cannot be saved against the next one, and switching to a condition that measures something else clears a level that no longer applies. The save action now matches the other market-state sheets. A new `SelectField` primitive, built on Radix Select, backs the described options.
- The GUI portfolio page now opens on the three figures a holder checks first. Market value, today's change, and total gain sit in one divided header band with the allocation donut and its legend beside them, all in tabular numerals with the signed colour rule intact. Partial totals stay explicit next to the total they qualify, and a degraded quote age stays attached to the market value it applies to. The holdings table lost a column of empty action cells and two columns of duplicated figures: today's move and total gain each state currency and percent in one cell, allocation rides under the value it comes from, the sparkline steps aside on narrow desktops, and quantity and average cost return once the ticker column can still hold a company name. Lot actions moved into the same row menu the watchlist uses, with removal confirmed in a dialog. While quotes load, the stats, the allocation and the table render skeletons shaped like the elements they replace, at the same size, so nothing shifts when the data arrives. The page and its table now fill the desktop canvas instead of floating above white space, and the mobile summary rows, expandable holdings, and per lot detail keep working at narrow widths.
- The GUI watchlist page is now a full-canvas workbench: a quote board that takes the available width with a sticky column header and its own scrolling, beside a fixed symbol rail. The trend column is chart only with no label or caption, the change column is one signed line with the percent inline, and an extended-session price renders as an amber pre-market or blue after-hours chip inside the price column instead of a sub-line drifting across columns. The row shown in the rail is marked as the current selection while the rail is on screen, the volume column steps aside in the width band where the rail claims the space it needs, and the table keeps stable column widths at every desktop size. In the rail, the ticker itself links to the symbol page, the primary action is Create alert, and removal is a quiet secondary that still confirms first.
- Hosted relay now admits the exact Finnhub quote/company-news and London Strategic Edge candles/financial-reports endpoints behind its existing credential, body, timeout, and rate-limit boundaries, allowing browser-local keys to unlock their existing hosted tools.
- Codex PR reviews are now advisory instead of merge-blocking: the polling review gate was removed, while reviews can still run automatically when a PR is created or be requested manually with `@codex review`.
- Hosted relay authorization now exchanges a one-time Turnstile proof in the trusted top-level shell for a short-lived HMAC token bound to the installation client id. Only signed, memory-only authorization enters WebContainer, whose shared provider and Pi Fetch calls stream through a bounded exact-path browser bridge; local GUI and TUI networking is unchanged.
- Hosted web now keeps one canonical Pi session per saved session, persists exactly-once action fingerprints across runtime failover, shares live event projection, stateful market tools, exact-symbol policy, quote and portfolio snapshot assembly, typed requests, provider metadata, model lookup, and Pi thinking controls with local GUI/TUI, and removes the earlier hosted HTTP server, completed-response stream fallback, market-state command interpreter, and parallel event adapter.
- Hosted web now creates Pi's canonical `AgentSession` through the shared OpenCandle session core and uses Pi's concrete `ModelRuntime`, provider implementations, model discovery, authentication, streaming, completion, command dispatch, retries, context accounting, compaction, and extension lifecycle for the full browser-safe OpenAI, Anthropic, and Google catalogs. A provider-restricted raw relay path carries those unchanged Pi streams across model APIs that reject browser CORS, without a second hosted model client or credential persistence. This replaces both the OpenAI-only compatibility client and the partial hosted session shim. The local GUI, TUI, and hosted web share provider metadata, model selection rules, routing behavior, attachment parsing, `ask_user` lifecycle, tool/workflow metadata, and canonical Pi session records; hosted credentials remain provider-scoped browser secrets.
- DuckDuckGo Web and News search now uses the provenance-backed `ddg-kit` client, pinned to its audited `0.1.0` release, adding bounded requests, typed provider failures, bot-challenge cooldowns, and Web representation fallback while preserving OpenCandle's provider cascade.
- The public Comparisons page now grounds the chatbot comparison in observed head-to-head benchmark behavior — fabricated filing and sentiment specifics, missed same-day market moves, per-share versus per-contract option slips, and absent saved-portfolio context — and names where general chatbots legitimately win (conceptual education and judgment-heavy personal finance).

- The public homepage and docs now present the local browser GUI as OpenCandle's primary path and the terminal as an equally complete keyboard-first interface, backed by the same tools, workflows, evidence, saved sessions, and market state.

- The homepage now removes redundant labels and interface copy, uses full-width tabs with inline unboxed icons for its GUI and terminal walkthroughs, compares illustrative ChatGPT, Claude, and OpenCandle answers by visible evidence, presents extension as a provider-to-tool-to-workflow path, places the install call to action after common questions, and uses direct punctuation throughout every published docs page.

### Fixed

- The web app no longer claims scheduled automation it does not have. The hosted Settings automation note says alert checks and reports run on demand, and the report schedule form offers no time or save controls in the web app, where a saved schedule would persist a value nothing consumes; the local app keeps its schedule form and copy unchanged.
- Dead Cloudflare Turnstile configuration no longer ships with the hosted app: the content security policy allowances for challenges.cloudflare.com, the unused Turnstile site key file, and the relay worker's unused secret type are gone, so the shell's published CSP now matches the documented claim that startup depends on no third-party challenge script.
- The first-run onboarding dialog now opens once and never flashes. The local and hosted browser GUI record per browser profile that the dialog has been shown, and it auto-opens only when that record is absent and a real setup broadcast positively reports a missing model. The record is written the moment the dialog opens, so reading it and navigating away counts, and starting a new chat, changing page, reloading, or opening a second tab no longer reopens it. A returning browser no longer flashes the dialog during boot: the connection's placeholder requirement and the transient non-ready requirement a reload reports before stored keys resolve both leave the dialog closed, so the instant open and close that could interrupt its exit animation and strand a dead dialog over the app is gone. Clearing keys or a later setup regression no longer reopens it either; setup stays reachable from the composer's model chip and from Settings, and drafting stays available throughout. Hosted "clear all" forgets the record along with the rest of the browser state, so a wiped browser is a first-timer again.
- The chat thread's Latest control no longer reserves a white row between the transcript and the composer. It floats bottom-center over the transcript as the same quiet 28 pixel pill the hosted status uses, takes pointer events only on itself, and keeps its widened pointer target.
- The magnifier in the ticker search and in the watchlist, portfolio, and alert list filters is vertically centred again. Both icons sat at a fixed offset that only landed on the centre line at one field height, so the ticker search icon rode 4px high on phones and the list filter icon sat 1 to 3px high everywhere. They now centre against the field the way every other icon in an input already does.
- Saved price alerts on a non-USD listing no longer read as dollars. The rule sentence and the observed values behind it now use the instrument's own currency, so a EUR listing reads "Price crosses above EUR 168.64" instead of restating the level as a dollar amount the alert never used. Rules whose instrument cannot be resolved keep the plain label rather than guessing a currency.
- The hosted runtime status no longer floats over the top right corner of the app, where it covered the primary action on the watchlist, portfolio, and alert pages at desktop widths. It now takes its own row under the app, so it stays visible while booting, ready, offline, and after an error without sitting on top of anything, and its data menu opens upward only while the reader opens it. The status chrome also uses the app's real design tokens again, so its border, surface, and state colors render instead of falling back to transparent. The local GUI is unchanged.
- A holding the portfolio cannot convert into its base currency now keeps its own price, day change, value, and gain on the portfolio page, stated in the holding's currency, instead of showing empty cells while the watchlist shows live prices for the same symbol. The base-currency market value, today's change, total gain, and allocation still leave that holding out, its row says it is kept out of the total instead of claiming a share of the portfolio, and the existing note naming the excluded symbols is unchanged. Holdings whose quote currency is unknown, or whose quote is unavailable, stay explicitly unknown as before.
- The quote freshness badge no longer prints raw minute counts such as "Quotes 1051m old". Minutes are used only for the first hour of staleness; past that the badge names the day the data is from ("As of Aug 4"), falling back to whole hours when the data is still from today. Fresh quotes stay silent as before.
- Sparkline cells in the local and hosted browser GUI no longer print the chart data provider's name. The per-row caption under every watchlist, portfolio, dashboard, and mobile sparkline is gone, along with the provider-named tooltips and image description; the as-of date stays in the chart's accessible description. The as-of date stays reachable on the chart itself for pointer readers as well as assistive technology, while list-level freshness stays with the quote badge. Loading sparklines now render a shaped skeleton instead of two lines of placeholder text, and the portfolio value card shows skeleton stats instead of a sentence while totals load. Skeletons stop pulsing for viewers who prefer reduced motion.
- Saved portfolio pages no longer blank every quote-derived column while the watchlist shows live prices for the same symbols. When a quote refresh resolved before the first saved-state response, the browser compared the incoming lots against a portfolio list it had not loaded yet, read that as a portfolio edit, and discarded the freshly fetched portfolio quotes and totals until the next five-minute quote refresh. Price, Value, Change, Total Gain/Loss, and % of Portfolio now populate on first paint, and the portfolio value card no longer sits on "Totals appear once quotes load." Quote-derived rows are still cleared for a real portfolio edit. This affects the local and hosted browser GUI, which share the market-state polling hook.
- A model-key save that fails over the local GUI WebSocket now shows its reason inline in model setup, matching the HTTP fallback and hosted paths. Previously only literal "Key was rejected by …" rejections rendered inline, so a key that could not be verified produced a toast the user could miss while the setup panel looked unchanged. GUI socket error frames now echo the failing request's action id, so a failure is attributed to the request that caused it rather than to whatever happened to be in flight. An error shown inline in model setup is no longer also raised as a toast: it duplicated the message the user was already reading, and the toast's own dismissable layer sat above the setup dialog and swallowed the first Escape.
- Shared ticker suggestions now remain selectable from Watchlist, Portfolio, and Alert panels instead of being dismissed as an outside click when rendered above a sheet.
